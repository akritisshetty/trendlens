     (frontend, a 2nd terminal)
     cd frontend && npx tsx server.ts            # React frontend on :3000

   [If you have no data yet]
     ./run.sh                                    # runs pipeline (10-day) then servers
     (needs APIFY_API_TOKEN in .env)

   [Optional CLI sanity check the questions resolve]
     python -m src.rag "How should I style my hair?"
     python -m src.rag "What cafe aesthetic is rising this week?"

B) Verify before presenting:
   - curl http://127.0.0.1:8000/api/health   -> status ok
   - http://localhost:3000 opens the homepage
   - First-ever run downloads CLIP/BLIP/sentence-transformers weights. Pre-download
     them so the demo doesn't stall.  (You saw this happen while testing.)
   - Keep the terminal where the backend logs are visible; if something errors,
     you can see it — but the frontend shows an honest "backend offline" message,
     never fabricated data.

C) Ports used by the system:
   - :8000  Python backend (src/api.py)
   - :3000  React frontend, Express dev server (frontend/server.ts)
   - (24678 vite) — killed/restarted by run.sh
   run.sh kills stale processes on these ports first.

HOW THE PIECES FIT (if a teacher asks "what is Flask/FastAPI?")
   The backend is NOT Flask or FastAPI. It is Python's standard-library
   http.server (src/api.py) — deliberately zero-dependency so it runs on free
   tier/Colab. The React frontend has an Express server (frontend/server.ts)
   that PROXIES every /api/* call to the Python backend. The frontend never
   fabricates results — if the backend is down it says so explicitly.

PART 4 — RESULTS SLIDE (spoken points; pick 2-3 numbers, don't read all)
------------------------------------------------------------------------------------
"On the Results slide you see two screenshots — the homepage and the chat.
Here are the numbers behind them."

- CLUSTERING QUALITY (why HDBSCAN):
    HDBSCAN on UMAP 15-d gives 18 clusters over 461 posts (82 unassigned as
    noise, 82% assignment coverage), and is chosen over UMAP 10-d and 20-d by
    a paired 80-split test: mean held-out rho 0.248 vs 0.170 / 0.177.
    No ARI/NMI "vs cluster ground truth" is quoted because there is no
    ground truth here - the labels ARE the clustering. Stability is measured
    the honest way instead: cluster identity across re-projections.

- THE HEADLINE RESULT — "trends before they have a name":
    Inside our visual clusters, the mean HASHTAG overlap (Jaccard) is ~0.024
    and keyword overlap ~0.03. Meaning: posts grouped by VISUAL similarity
    share essentially NO words. A hashtag/Google-Trends/keyword tool has no
    query term to run — the trend exists only at the image level. This is our
    unique advantage.

- WHY CLIP:
    CLIP ViT-B/32 = 10.5 img/s, ~165 ms/image. CLIP ViT-L/14 is 21x slower
    (0.5 img/s) for essentially no gain. DINOv2 has far lower intra-cluster
    coherence (~0.08 vs CLIP's ~0.50).

- RAG RETRIEVAL:
    Hit rate @3 = 0.75, @5 = 1.00; MRR 0.68. Scope-gate accuracy 0.86 (lets in
    relevant queries, rejects irrelevant ones — like the Python question).

- TREND SCORING:
    Our composite score (growth x size x stability) correlates +0.5 with real
    engagement, while naive "simple growth" is NEGATIVELY correlated (-0.87).
    Story: real growth matters, but volume and stability are what predict
    engagement — naive growth alone misleads.

- PERFORMANCE:
    Incremental run ~15s (KNN assign skips UMAP+HDBSCAN); CLIP ~200ms/image;
    UMAP+HDBSCAN+trends under 0.5s total for the batch.

PART 7 — ANTICIPATED QUESTIONS (quick answers)
------------------------------------------------------------------------------------
Q: "Why are there no learning-rate / epochs / optimizer hyperparameters?"
A: "TrendLens uses pre-trained models (CLIP, BLIP, LLM) plus classical ML
   (UMAP, HDBSCAN, FAISS) — there's no neural-network training loop, so no
   LR/epochs/optimizer. The hyperparameters are the algorithm settings —
   UMAP neighbors, HDBSCAN cluster size, growth thresholds, retrieval k, LLM
   temperature — which I benchmarked, not guessed."

Q: "The frontend says backend offline — is it broken?"
A: "No — by design, the frontend NEVER fabricates data. If the Python backend
   is down it returns an explicit offline message. Start it and everything works."

Q: "What is Flask / FastAPI in this project?"
A: "Neither. The backend uses Python's standard-library http.server to stay
   zero-dependency and free-tier friendly. The React frontend uses Express only
   as a dev/proxy server that forwards /api/* to the Python backend."

Q: "Why UMAP before HDBSCAN?"
A: "HDBSCAN works poorly in very high dimensions (512-d). UMAP projects to a
   10-d manifold while preserving neighborhood structure, making density-based
   clusters cleaner. Benchmark: silhouette 0.58 vs KMeans 0.48."

Q: "How do you keep cluster IDs stable across runs?"
A: "The Cluster Tracker. Baseline run locks cluster centroids; later runs use
   FAISS KNN to assign new images to existing clusters (similarity >= 0.25) and
   form micro-clusters (>= 3 unassigned) when needed. Stable UUIDs enable real
   time-series trend tracking instead of reshuffling every run."

Q: "Is the data real?"
A: "Yes. Instagram posts, timestamps, likes, comments, views come from public
   accounts via Apify — not synthetic. Only the cluster NAMES are BLIP/VLM
   interpretations of the visual content (those are labels, not ground truth)."

STACK AT A GLANCE
- Data: Instagram via Apify (81 accounts across food/fashion/photography/beauty)
- Embed: CLIP ViT-B/32 (512-d, L2)
- Reduce: UMAP (20-d, cosine, nn=15, min_dist=0.0)
- Cluster: HDBSCAN (min_cluster_size 5, min_samples 3, eom) + Cluster Tracker
- Caption: BLIP large (max_new_tokens 40); CLIP zero-shot style tags
- Verdict: formal trend definition (support/persistence/author-breadth/growth +
  binomial significance) -> Rising | InsufficientData, never "declining"
- Retrieve: FAISS IndexFlatIP over sentence-transformers (BAAI/bge-base-en-v1.5, 768-d)
- Generate: LLM (Gemini default, plug-and-play OpenAI/Ollama), temp 0.3
- Backend: Python stdlib http.server (src/api.py) on :8000
- Frontend: React 19 + Vite + Tailwind + Framer Motion, Express proxy on :3000
